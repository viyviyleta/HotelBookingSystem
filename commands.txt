Разбирая ваш лог, видно, что пункт **`5`** отправляет команду `InvalidOp` (неизвестная операция) и получает ожидаемый ответ от сервера `Success: False, Message: Unknown operation: 'InvalidOp'`.

Ниже приведена полная шпаргалка по всем пунктам этого меню: **что именно делает каждый пункт** и **как правильно его продемонстрировать**.

---

### Подробный разбор пунктов меню клиента

#### **`1. Check Availability` (Проверка доступности)**

* **Что делает:** Отправляет запрос `CheckAvailability` с номером комнаты и датами.
* **Как тестировать:** Выберите пункт `1`, введите номер номера (например, `101`). Сервер вернет статус номера (свободен/занят).

---

#### **`2. Create Booking` (Создание бронирования)**

* **Что делает:** Отправляет запрос `CreateBooking`.
* **Как тестировать:** Введите номер `101` и даты (например, `2026-10-01` и `2026-10-05`). При успешном бронировании сервер возвращает `SUCCESS` и уникальный `BookingId`.

---

#### **`3. Pay Booking` (Оплата бронирования)**

* **Что делает:** Отправляет запрос `PayBooking` по ID брони.
* **Как тестировать:** Передайте `BookingId`, полученный на шаге 2. Статус брони на сервере изменится на «Оплачено».

---

#### **`4. Cancel Booking` (Отмена бронирования)**

* **Что делает:** Отправляет запрос `CancelBooking`.
* **Как тестировать:** Передайте `BookingId`. Номер снова станет доступным для бронирования через пункт `1`.

---

#### **`5. Send Unknown Operation (Error Test)` (Тест некорректной операции)**

* **Что делает:** Отправляет на сервер заведомо невалидную команду (например, `"Operation": "InvalidOp"`).
* **Для чего нужен:** Демонстрирует преподавателю, что сервер не «падает» (не выбрасывает unhandled exception) при получении неизвестной команды, а корректно обработает ошибку и вернет JSON вида:
```json
{ "Success": false, "Message": "Unknown operation: 'InvalidOp'" }

```



---

#### **`6. Show my local time (skewed clock)` (Локальное время со смещением)**

* **Что делает:** Показывает текущее время на стороне клиента с учетом искусственной задержки/смещения часов (переданного через флаг `--offset`).
* **Для чего нужен:** Чтобы наглядно увидеть, насколько часы клиента «рассинхронизированы» с системным временем.

---

#### **`7. Sync time with server` (Синхронизация времени)**

* **Что делает:** Выполняет алгоритм синхронизации часов с сервером (Часть 2 лабораторной работы).
* **Как работает:**
1. Отправляет запрос времени на сервер.
2. Запрашивает искусственную задержку ответа от сервера (например, `0` или `3000` мс).
3. Вычисляет **RTT** (круговое время задержки сети) и рассчитывает поправку часов по трем методам: **Naive**, **HalfRTT (Кристиан)** и **Averaged (NTP)**.



---

#### **`8. Concurrent reserve race` (Тест гонки потоков)**

* **Что делает:** Автоматически запускает внутренний сценарий `RunRace` из файла `ScenarioRunner.cs`.
* **Как работает:** Создает параллельные TCP-потоки, которые синхронно отправляют запрос на бронирование одного и того же номера (например, `101`).
* **Что показывает:**
* Если сервер запущен с `--sync none`, несколько запросов вернут `SUCCESS` (Race Condition / Овербукинг).
* Если сервер запущен с `--sync lock` или на базе `SemaphoreSlim`, ровно 1 клиент получит `SUCCESS`, остальные — `FAIL`.



---

#### **`9. Error handling checks` (Пакетная проверка ошибок)**

* **Что делает:** Автоматически запускает сценарий `RunErrorChecks` из `ScenarioRunner.cs`.
* **Что проверяет:** Последовательно отправляет 8–9 вариантов некорректных данных (несуществующий номер `999`, повторная оплата, отрицательная задержка времени, битый JSON) и выводит ответы сервера.

---

#### **`0. Exit` (Выход)**

* Закрывает TCP-соединение и завершает работу консольного клиента.
